# Web-master panel

Self-hosted open-source дашборд на Nuxt для аудита и мониторинга всех ваших сайтов на одном экране.
Инструмент создан для разработчиков, которым важно держать под контролем всё в одном месте:
проверку доступности (/health), SEO-показатели, заголовки безопасности, метрики Unlighthouse, свежесть зависимостей,
а также сроки оплаты доменов, хостинга и SSL-сертификатов.

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env
npm run dev        # http://localhost:3000
```

## Переменные окружения

Смотрите `.env.example`. Nuxt сам подхватывает переменные вида `NUXT_<KEY>` в `runtimeConfig` (`nuxt.config.ts`) — `process.env` в самом конфиге указывать не нужно, только пустые строки по умолчанию.

## Скрипты

```bash
npm run dev            # dev-сервер
npm run build           # прод-сборка (.output/)
npm run lint            # eslint
npm run lint:fix        # eslint --fix
npm run format           # prettier --write
npm run format:check    # prettier --check
```

### Health-check (`/health`)

`server/routes/health.get.ts` — минимальный `{status: "ok", timestamp}`. HTTP-код всегда 200 

## Известные нюансы тулчейна

- **`h3`** и **`typescript`** зафиксированы на точных версиях (без `^`) намеренно — `@typescript-eslint` (через `@nuxt/eslint`) пока не поддерживает экосистему вокруг новых мажоров (TS7/h3 v2) целиком, обновление может сломать линт без явного решения это сделать. Перед тем как снимать пин — проверьте вручную, что `npm run lint` не падает на новой версии.
- **`vue-tsc`** не зафиксирован жёстко (`^3.3.x`) — даже патч-версии этого пакета иногда вносят собственные регрессии в тайпчек при билде (`npm run build` может начать шуметь ложными ошибками вида `Cannot find name 'onMounted'` для файлов в `app/composables/*.ts`, хотя сборка не падает). Если такое увидите — проверьте, не обновился ли именно `vue-tsc`, прежде чем чинить код.
